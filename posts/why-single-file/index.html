为什么我把课件做成单文件 HTML

2026-10-26 · 1199 字 · 约 3 分钟 教学工具离线优先技术随笔

上课的时候最怕两件事：一是教室网络突然没了，二是投影电脑上没装那个软件。

这两件事我遇到过不止一次。后来我的课件就都变成了这样：一个 .html 文件，双击就能打开，断网也能跑，拷进 U 盘带到任何一台电脑上都不用装东西。

单文件的代价

说实话，单文件是有代价的。

所有样式、脚本、图片、甚至 3D 引擎，都要塞进同一个 HTML 里。我最近做的光合作用课件是 747 KB，啤酒发酵那个是 775 KB，里面内联了一整个 three.js。

这带来几个麻烦：

  • 改一行 CSS，产物就要重新打包
  • 没法用 import，所有模块得按顺序拼起来
  • 调试时看不到源码行号（因为都压在一行里了）

所以我给自己定了几条规矩。

三条规矩

第一条：源码永远分开写，产物才是单文件。

src/ 目录下是正常的 .html / .css / .js，一个构建脚本把它们拼成一个文件。构建脚本只有几十行，用的全是标准库。

第二条：构建时必须校验零外链。

拼完之后扫一遍产物，只要发现任何 src="http...、<link rel=stylesheet>、fetch()、WebSocket，直接中止构建。

这条规矩救过我一次。有个版本我顺手引了个 CDN 上的图标库，本地测试完全正常，因为我的电脑有网。构建脚本拦住之后我才意识到：这文件拿到没网的教室里就是个白屏。

第三条：行尾统一 LF。

这条听起来很无聊，但坑很深。Windows 上 Python 写文件默认会把 \n 转成 \r\n，于是本地是 751,385 字节、git 提交后变 747,662 字节，MD5 对不上，你会怀疑自己改坏了东西。

正确写法是：

with io.open(out, 'w', encoding='utf-8', newline='\n') as f:
    f.write(html)

那个 newline='\n' 是关键。

为什么不用「在线平台」

有人问为什么不干脆做成网页服务，学生扫码就能用。

我的顾虑是：

  1. 教室里没有稳定网络。这不是假设，是常态。
  2. 学生的作品不该上传到我的服务器。像班主任工作台那种记学生信息的工具，数据留在浏览器本地（localStorage）比存在任何服务器上都让我安心。
  3. 十年后这些文件还能打开。一个 HTML 文件，只要浏览器还在，它就还在。而一个需要后端、需要数据库、需要域名的系统，三年后大概率打不开了。

现在的做法

现在我的每个教学工具都是同一个形态：

项目体积里面有什么
光合作用演示747 KBthree.js + 生理模型 + 16 个课堂问题
啤酒发酵工厂775 KBthree.js + 十步工艺流程 + 剖切视图
班主任工作台362 KB自研 XLSX 引擎 + 23 个管理模块

做完就放到 应用集 上，一个链接发给同事，他双击就能用。

这件事最舒服的地方在于：我不需要维护任何服务器。
